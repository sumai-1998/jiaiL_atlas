# WorldWarp 原版基线再次审计（2026-09-21）

**结论：历史生成与评分执行完成，但成功的质量复现尚未完成。已确认本地适配曾遗漏内参平均；该项修复未解决质量问题。当前证据指向首段几何条件失真、跨段两套运动/几何估计不一致和扩散后的结构变化，但没有经过受控新推理证明唯一根因或完整修复。**

本次重新阅读实际代码、原论文与已保存中间结果，执行 CPU 数值核查并比对当前官方源码。没有新 GPU 推理、模型修改或替换历史分数。[可复核数据](../../../../Reports/dl3dv_baseline_audit_20260921/audit.json)、[审计脚本](../../../../Reports/dl3dv_baseline_audit_20260921/audit.py)。脚本依赖原运行目录；报告图片链接复用已有报告，不是独立媒体包。

## 1. 已确认的适配问题与修复结果

旧本地 `calibrate` 直接使用逐帧预测内参，遗漏上游将主点居中、K 在时间上平均的处理。此项是本地实现差异，已在 9 月 18 日修复并完整重跑。

但它不是全部原因：旧五场景第 50 帧控制焦距相对数据集标定为约 1.105–1.467 倍；时间平均不能消除系统偏差。建筑与雕像场景修复后第 200 帧 PSNR 仍为 11.066 dB，LPIPS 为 0.7157，主体明显偏离。数据集标定 K/旋转、另做平移单位换算的诊断也失败，第 200 帧 PSNR 10.972 dB。后者是诊断协议，不是正式原版复现。

参考视频提取相机本身有[论文补充材料 §7](https://arxiv.org/html/2512.19678v1#S7)依据；不能因为使用了预测参考相机就认定流程错误，也不能因此接受任意视角的输出。

## 2. 失真不只出现在最后的评分或视频编码

抽看已有首段第 25/49 帧，GS 粗渲染已经出现雕像/立柱边缘拉伸、重影和大块无支持区域。随后生成又改变主体与构图，最后第 200 帧雕像丢失。

![首段 GT 与扩散前几何渲染](../../../../Reports/dl3dv_baseline_recheck_setup_20260918_1438/first_geometry.jpg)

![第 200 帧四格对比](../../../../Reports/dl3dv_worldwarp_recheck_20260918/frame_200.jpg)

空洞本身是新视角补全的正常输入，不应将所有空洞视为错误；真正需要验证的是已有表面的位置/形状偏差，以及生成是否在可靠区域保留了结构。

因此，只重算指标不能修好视频；只换一条目标轨迹也已经证明不足。下一步需要分别隔离源深度、源内参、相机运动和扩散的影响，不能把这些观测直接归因于模型能力上限。

## 3. 本轮新增数值证据：跨段两套相机不一致

后续段将历史 49 帧的相机替换为 TTT3R 新估计的相对位姿，未来目标相机保留参考轨迹；两者均以历史最后一帧为原点。此操作确实存在于上游实现，不是本地独有改动。

本次在 `upstream_mean` 重验保存的 NPZ 上重新计算：

| 即将生成的段 | 建模源帧中最大的旋转差异（度） | 49 帧历史平移最小二乘比例 |
|---|---:|---:|
| chunk_001 | 2.687 | 0.633 |
| chunk_002 | 3.486 | 0.827 |
| chunk_003 | 3.034 | 0.819 |
| chunk_004 | 3.542 | 0.835 |

旋转差异比较的是末尾 5 张建模源图的 TTT3R 位姿与请求位姿；比例拟合的是同一历史窗口中两套平移，只有一个正向标量，没有旋转拟合。

**这些不是独立测量的生成轨迹真值，也不能把 0.633 解释为真实尺度少了 36.7%。** 它们可能混合生成运动偏差、预测误差和坐标单位差异。第一段是重复首图，不能把其估计的静止历史与请求的运动轨迹直接比较，故此表只列后续段。

可确认的是跨段两套估计并不一致，代码中没有在该处显式校准其尺度。能否造成当前程度的失败，需固定历史做受控渲染/生成实验。不能直接乘上表中比例然后宣布修复。

## 4. 本轮新增源码对照

从官方 `HyoKong/WorldWarp` 当前 main 下载源码并保存于本目录 `upstream/`；SHA-256 见 audit.json。以下函数抽象语法树与本地一致：

- `sample_sequence`、`flow_matching_sample_step`、`run_inference_chunk`。
- `warp_with_validity_mask`、`_initialize_splats_from_depth`、`_train_splats`、TTT3R `inference`。

这排除了这些函数内部存在本地独有改写的解释，**不等于整个执行入口、依赖环境、预处理、配置和评分与作者实验完全一致**。此前已保存的权重核验也仅证明作者 checkpoint 文件及 825 个加载张量一致，不证明整个复现成功。

## 5. 指标是否算错

本轮从无损 PNG 独立重算重验场景第 1/50/200 帧 PSNR，与原 JSON 一致（容差 1e-9 dB）。第 1 帧约 43.07 dB；这不支持“首图一读入就彻底错了”的解释。查看源代码，PSNR 使用 RGB [0,1]，LPIPS 输入转为 [-1,1]；未发现这一层显然的范围错误。此次没有重新运行 LPIPS、SSIM、FID 或 DUSt3R 网络。

位姿评分有独立估计噪声。从原五场景保存结果提取，对真实 GT 视频本身使用 DUSt3R 后，第 200 帧旋转误差为：

| 场景 | GT 视频的 DUSt3R 旋转误差（度） |
|---|---:|
| 建筑与雕像 | 3.582 |
| 温室 | 8.566 |
| 餐厅 | 1.205 |
| 商铺 | 1.887 |
| 汽车展厅 | 1.395 |

因此不能把生成结果的位姿分数当作无噪声真值，也不能直接减去 GT 估计误差。结构崩坏的生成图可能更加难以估计，单个 R/t 分数改善不保证视觉对齐。

论文[§5.1](https://arxiv.org/html/2512.19678v1#S5.SS1)描述 DUSt3R 位姿、相对首帧与最远位移归一化；当前公式有依据。但本地稀疏选帧、优化参数、LPIPS 骨干等不能认定与作者隐藏评测细节逐项相同。论文 §5.2 还出现 Master3R 的文字表述，与 §5.1 的 DUST3R 不一致；这需要官方评价代码或作者澄清，不能擅自换估计器后声称官方分数复现。

五场景端点 FID 只有 5 个样本，只作诊断；单场景端点 FID 为 N/A。全视频 FID 与端点 FID 不能混比。数据源只有 480×270，裁剪放大至 720×480；原始采样速度、官方测试划分与帧抽样没有完全对齐。当前选中时间标记为 1–225、间隔 1，并不能由此推出原始拍摄 fps。

## 6. 应如何修正复现工作方式

此前把执行完整与效果验收混在一起，又在未得到可信原版效果时扩展组合评测，是实验组织上的问题。已有视频与分数保留为本地适配结果，但不能用于宣称论文复现成功或隔离某个几何模块优劣。

建议下一轮先固定一个场景的首段及第一次跨段：

1. 在固定输入上测试原参考 K 与标定 K/不同几何解释下的渲染，检查已有支持区域的几何；固定目标轨迹，不通过事后对齐提高正式分数。
2. 固定首段生成历史，单独比较后续源位姿/尺度处理，其他变量不动。检查是否改善下一段条件，而非仅让源图更容易拟合。
3. 固定相同粗 RGB、mask、文本和上下文后检查扩散条件遵循；再考虑 strength 对照，不同时替换几何和噪声。
4. 若需验证扩散本身，用独立合成场景的精确几何构造单独标记的诊断上限。未来 GT 深度/RGB 不进入正式单图生成基线。
5. 短段的相机、结构和衔接验收通过后才扩展完整五场景。仍无法对齐官方协议时，应明确交付本地协议结果，不能改名为成功官方复现。

本轮没有实现或验证上述修复。审计完成不等于基线已修好。
