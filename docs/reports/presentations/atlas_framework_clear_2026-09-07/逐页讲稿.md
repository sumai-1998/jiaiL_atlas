## 05｜官网给出模型骨架；GS 闭环是我们的实现假设

开场句
你的框架可以作为一致且可实施的功能分解；需要区分的只是哪些是官网披露，哪些是工程推断。

展开讲
1. 官网明确披露统一的多模态自回归扩散 Transformer，空间上下文包含图像、深度、相机等；它能生成并做空间重建，也展示了点云与 GS 结果。
2. 官网没有给出长期 GS 在每轮中的完整读写算法，也没有证明生成与重建对应两个独立模型。我们把这些功能拆开，是为了便于复现与控制状态。
3. 因此既不用否定这个猜想，也不把具体三参考输入、Marble-like 初始化器、永久 GS 地图写成官方网络事实。

过渡句
接下来不再反复讨论边界，直接沿这张可实现的功能框架展开。

## 06｜先初始化，再开始四步循环

开场句
第一轮和后续轮的工作不同，首先必须得到一个可以渲染的起始区域。

展开讲
1. 单图或多图先形成符合输入的局部 3D 表达；文本入口可先生成参考图，再初始化几何。这里只规定功能，不强制所有入口走同一个网络。
2. 初始化还要留下参考 RGB、首帧 GS 渲染、相机与尺度锚。纯文本生成的参考不是 GT；只有真实观测才可以按其条件讨论观测真值。
3. Marble-like 表示输入到初始三维区域的能力，不要求调用 Marble，也不表示已有开源项目能完全达到其效果。

过渡句
有了起始世界，下面按顺序看第一步：从它渲染一个新视角。

## 07｜① 渲染：告诉模型，世界里已经有什么

开场句
渲染图是一份几何约束：这个相机位置上，已有世界应该长什么样。

展开讲
1. 输入是当前地图与目标相机，在固定时刻查询；输出包含粗 RGB、深度，以及哪些像素有可靠几何支持的有效性信息。
2. 缺口、遮挡后新暴露的区域和低置信区域交给下一步生成；不要把所有 alpha 或深度有效像素都等价为高质量真值。
3. 右图来自本地 3 帧输入建立的 GaME 场景，在输入相机上重渲染。它仅说明 GS 可渲染，非 Atlas 的结果，也不是专门的新视角质量验证。

过渡句
粗图提供了空间骨架，但它可能有洞或者粗糙，第二步负责生成完整画面。

## 08｜② 生成：保持已知部分，补全新暴露区域

开场句
这一模块不是凭空生成下一帧，而是在空间约束和历史参考下补出新视角。

展开讲
1. 你的三类条件很自然：当前目标视角的 GS 渲染；初始参考 RGB 与其 GS 渲染；历史图像、相机等空间上下文。
2. 初始参考帮助维持外观，粗渲染帮助维持几何，历史上下文用于关联不同视角。三组是功能描述，不是官方公布的精确张量拼接方式。
3. 官网统一模型可输出图像和深度；开源 MVP 可先输出 RGB，再交给独立几何模型。WorldWarp 通常按视频 chunk 生成，不应直接称为官方逐元素 AR 复刻。

过渡句
新画面出现了，但它还只是候选内容，接下来必须把它变成有坐标的几何。

## 09｜③ 重建：把新图变成可融合的几何

开场句
重建这一步解决的不是画面好不好看，而是每个像素究竟位于世界的哪里。

展开讲
1. 输入应包括新帧与重叠的历史关键帧。工程目标是利用已有相机或几何锚，约束当前批次的尺度和位姿。
2. MapAnything 输出深度、pointmap、相机内外参等；pointmap 是每个像素对应的三维点，不等于已经具备长期状态的地图。
3. 右图是本地测试第 0 帧的预测 z-depth，经 2–98 百分位归一化着色，仅为了说明几何中间量。当前包装器还是 RGB 入口，已知相机条件尚未接入其 CLI。

过渡句
这些点有了三维坐标，但还不能直接拼进旧地图，第四步负责对齐和更新。

## 10｜④ 融合：让新几何进入旧地图

开场句
融合的关键不是再导出一个 PLY，而是让这轮结果成为同一个世界的新版本。

展开讲
1. 先用重叠区、相机约束或几何匹配，把新批次对齐到旧世界的尺度与坐标。
2. 再检查投影一致性、可见性和置信度，避免生成错误覆盖已知可信区域；必要时只接受部分新区域。
3. 最后为新增区域补 GS，并联合优化、剪枝；保存更新后的地图与必要优化状态，下一轮继续使用。GaME 可承担后半段，但坐标对齐、门控和跨进程恢复仍需工程适配。

过渡句
到这里我们已经有一份世界地图，但图像生成还需要另一种记忆。

## 11｜两种记忆，各管一件事

开场句
只保存 GS 不一定能保住所有外观细节，只保留视频历史又缺少明确的空间锚。两者互补。

展开讲
1. 世界状态侧保存空间几何、可见性和场景版本，用来在目标相机下渲染。
2. 参考记忆侧保存初始参考、首帧 GS 渲染和选出的历史关键帧及相机；新帧经过筛选后才加入，避免无限增长。
3. 两路记忆必须共用相机、尺度、时间标识。这里参考上下文是工程机制，不等价于无限大的模型上下文窗口。

过渡句
把这两种记忆放回闭环，看一轮结束时到底发生了哪两次更新。

## 12｜一轮结束：地图更新，历史也更新

开场句
完成一轮以后有两条反馈：融合结果进入世界状态，选中的新帧进入参考记忆。

展开讲
1. 下一轮从更新地图渲染，生成器同时读取更新的参考记忆。这样新探索区域有机会成为后续视角的约束。
2. 新帧不是无条件全部收录；通常要按覆盖、置信度和冗余选关键帧。图中的记忆管理是复现设计，当前包装器尚未实现完整调度。
3. 至此系统机制讲完。后面项目名称只是在这四个位置上填入开源实现，不再变换框架。

## 14｜开源组装：给四个功能各找一个执行者

开场句
现在四个框的含义不变，只把执行者填进去。

展开讲
1. 渲染位置用 gsplat 作为统一 GS 渲染接口的候选；GaME 自身核心用其 rasterizer，不应误写成已由 gsplat 替换。
2. 生成先用已安装运行的 WorldWarp 做基线。它自带 TTT3R 和局部 GS 条件构造，接入持久地图需要适配，不能整套直接替换后宣称联调完成。
3. MapAnything 提供几何，GaME 做地图增补和优化。跨轮坐标对齐、质量门控与 resume 属于中间适配器开发任务。
4. 原开源调研以 Spatia 为主候选，本次为降低首次联调成本把本地 MVP 指向现有 WorldWarp；这不是声称 Spatia 已被证伪。

过渡句
这里最容易混淆的是 WorldWarp 与 MapAnything 加 GaME 的关系，单独用一页讲清。

## 15｜WorldWarp 与 MapAnything + GaME：分工不同

开场句
WorldWarp 不是纯视频模型，它已经有重建与局部 GS；我们要增强的是持久地图这一侧。

展开讲
1. 本地 WorldWarp 从图像或上一段视频，用 TTT3R/CUT3R 恢复几何，创建并优化局部 GS，渲染目标相机条件，再用 Wan 衍生生成器生成下一段。当前调用每段重新创建 warper 与 GS，不是恢复长期全局 GS。
2. MapAnything 加 GaME 输入图像，输出几何、融合后的 GS 和重渲染，没有补出不可见新内容的生成器。当前一次调用内部多帧融合，下一次调用仍新建场景。
3. 所以 Map + GaME 可以承担 WorldWarp 里部分几何与地图职责，但不能替代它的完整生成链，也不能把当前离线串联说成已有永久地图闭环。

过渡句
先看我们确实做完的部分：图像到几何、到 GS，再到渲染。

## 17｜下一步：接通三个跨轮接口

开场句
完整闭环还缺的不是更多项目，而是这三处具体的状态交接。

展开讲
1. 接口 A：从持久 GaME 场景按目标相机渲染，将 RGB、几何有效性和必要深度转成 WorldWarp 接受的条件；需要匹配尺度、分辨率、mask 语义和生成器输入分布。
2. 接口 B：把新帧和有重叠的历史帧联合送给 MapAnything，并让已知相机、坐标锚参与几何推断或后对齐，避免每批次自由漂移。
3. 接口 C：在同一地图上继续 GaME 更新，管理 checkpoint、优化器、关键帧与新增区域检查；失败可以拒绝写入或回退。当前 CLI 没有这个跨调用 resume 路径。

过渡句
如何判断接线不是形式上接上了？用三道验收关来决定是否进入下一阶段。

## 18｜用三道关，验收静态世界闭环

开场句
验收顺序从已有证据出发，不直接跳到长时间 4D 演示。

展开讲
1. 第一关已经完成安装级验证：从图像得到几何、GS，保存后能重载再渲染；这不代表质量达到产品水平。
2. 第二关做两轮小范围相机移动，先固定 t，证明第二轮从第一轮世界状态继续，新增区域被复用、旧区不明显退化。保留地图版本、关键帧和接受 / 拒绝记录。
3. 第三关走 A 到 B 再回 A，加入保留验证视角与不同探索路径，观察回看一致、几何冲突与漂移；有 GT 才报告有意义的重建精度。

等静态闭环稳定后，再把时间这一维接进来。

## 19｜4D 放在静态闭环之后：分开调度空间与时间

开场句
你的直觉可以落实成两类操作：在同一时刻换相机，或者在同一相机推进时间。

展开讲
1. 空间探索保持 t 不变，沿前述静态四步循环扩展同一时刻的空间覆盖。
2. 时间推进保持 C 不变，生成新的物体状态或运动，然后建立可随时间查询的动态表达；它不只是把新帧混进一个静态 GS 地图。
3. 固定相机下生成动态画面本身可行，但单视角运动不能唯一确定 4D 几何，需要多视角、深度、运动先验或其他约束。调度上解耦不意味着底层物理、遮挡或神经网络完全解耦。

过渡句

## 21｜A1｜AR、扩散与场景时间，分别是什么？

开场句
这里澄清三种不同的轴，避免把 AR 和扩散误认为互斥。

展开讲
1. AR 指序列组织：在前面上下文条件下预测下一个元素。官网的元素可以包含不同模态，不能简单限制为按物理时间输出下一视频帧。
2. Rectified flow / 扩散指当前输出元素内部的生成过程，在潜空间中由噪声逐步恢复样本。
3. 物理时间 t 是场景状态查询条件，与序列索引 k、内部去噪步 s 是不同概念。固定 t 换相机仍可逐元素 AR 生成。

过渡句
落到开源组装时，接下来需要统一的不是网络形式，而是中间数据约定。

## 22｜A2｜统一中间格式：图像、相机、几何

开场句
这页适合交给具体写适配器的人，主讲时无需逐字段朗读。

展开讲
1. 当前 posed_rgbd.npz 保存 rgb、depth_z、valid、intrinsics、c2w、confidence；点图另存 pointmaps.npz。
2. RGB 使用 uint8 NHWC；深度是相机 z-depth，不是射线距离。批次内图像尺寸要统一，改变分辨率时要相应缩放完整 K。
3. 统一相机约定为 OpenCV c2w；进入 GaME 实际执行接口前必须求逆得到 w2c。本地另有完整 K 投影修正，不能删除这个适配器。
4. 独立 MapAnything 调用的世界原点和尺度不能默认一致；长期图需要坐标锚与重叠约束。pointmap 体素合并也不是 SLAM 的回环优化。

过渡句

## 23｜A3｜本地如何运行？两步，两个环境

开场句
两个项目通过 NPZ 文件交换，不需要把依赖硬塞进同一个 Conda 环境。

展开讲
1. 演示命令中的输入和输出目录需替换，GPU 需在执行时自行选择空闲卡；不要直接复用已有结果目录。
2. 两步都写 --max-views 3 是为了让实际使用帧数相同。默认 MapAnything 是 8，GaME 是 3；不改参数可能只让 GaME 使用前 3 帧。
3. 三帧是当前小测试设置，不是模型只能接三帧。两步至少一帧可走，但重叠多视角更适合验证几何一致性。
4. 当前包装器不是无限流式输入：更长序列受模型上下文、显存、地图大小约束。长期运行需窗口、关键帧筛选、持久状态和资源预算。GaME 原生 additions 变化分支还需更多已接受关键帧触发，三帧测试不覆盖所有分支。

过渡句

## 25｜A5｜4D 的关键，是覆盖“相机 × 时间”

开场句
这个网格表示观测组织方式：一列是同一时刻的多相机，一行是同一相机的时间序列。

展开讲
1. 不同视角、同一时刻用于约束该时刻的空间几何；同一视角、多个时刻用于约束运动和变化。每一个格子可以来自真实采集，也可能来自生成候选，但两类证据的可靠性不能混为一谈。
2. 单相机的一行视频缺少其他视角，并不能唯一确定遮挡后或背面的动态几何。要生成可自由换视角的 4D 资产，就要补多视角证据或引入额外深度、运动与结构先验。
3. NoPo4D 这类候选负责从时空观测重建动态表达；它不是独立决定未来物体怎么运动的生成器。

过渡句
最后一页给出资料阅读顺序和本地证据入口。
