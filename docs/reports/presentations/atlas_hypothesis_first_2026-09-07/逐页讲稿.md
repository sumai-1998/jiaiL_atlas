## 03｜先按我的假设，读懂这张完整闭环

开场句
我的假设是：同一个世界模型负责产生内容，GS 保存世界，空间上下文保存看过的参考。

展开讲
1. 多模态输入先经过初始化，得到局部 GS 和参考图。初始化与连续生成可理解为同一统一模型的不同使用阶段。
2. 一轮空间探索从当前世界选 C、t 并渲染；粗图和空间上下文进入统一模型，生成新视图及深度；增量融合把它们变成更新后的世界。
3. 上下文与世界状态同时反馈。这里生成与深度仍保留为统一模型假设，不提前按开源项目拆成两台模型。
4. 4D 不是最后被删掉的一小项，而是整个系统的另一类查询：固定时间探索空间，或固定相机推进时间。具体长期 GS 写回与模块拓扑是原综合假设，不当作官方未披露算法。

过渡句
第一步先看初始化：为什么需要同时产生一份世界和一份参考记忆。

## 04｜假设一：初始化同时得到世界与参考记忆

开场句
我的初始化并不只是生成一张漂亮图片，而是留下后续能继续使用的三维区域和参考。

展开讲
1. 单图、多图直接提供参考；纯文本先得到视觉参考，再结合深度和相机形成点云、GS。视频、多视角视频或已知几何也是原图保留的入口。
2. Marble 式表示输入到局部三维区域的能力。假设层可以由统一模型承担参考与深度生成，再转换成 GS；不是要求必须调用 Marble 产品。
3. 一份输出是可以渲染的初始 GS，另一份是首帧参考、首帧 GS 渲染及其相机等上下文。观测图可以作为 GT；由文本生成的首图应称参考锚点。
4. 此时空间世界与参考记忆已经有起点，之后不必每轮从头建立一个完全独立场景。

## 05｜假设二：小幅换相机，以三组图像条件补新视角

开场句
我先用已有 GS 渲染稍微变化后的相机视角：大部分内容还在，但新暴露处可能有洞或粗糙。

展开讲
1. 第一组输入是当前目标视角的粗 GS 渲染，可以带深度与可见性；第二组是首帧参考 RGB；第三组是首帧 GS 渲染。三组图像条件在这个版本里都明确保留。
2. 首帧参考约束外观，首帧 GS 渲染提供参考与三维表达之间的对应，目标粗渲染提供当前相机的结构。历史 RGB-D、相机、时间和文本一并进入上下文。
3. 统一世界模型按时序 / AR 组织生成，在空间条件引导下修整已有内容并补出未知区域，得到新 RGB 和深度。用户最初描述的新 RGB 帧，在综合假设图中保留了统一 RGB-D 输出能力。
4. 稍后开源实现会把 RGB 生成和几何预测拆开；这里先完整讲原假设，不提前替换为 WorldWarp + MapAnything。

## 06｜假设三：新帧回写 GS，也进入下一轮历史

开场句
我要求的不只是看到新画面，而是新画面里的新区域要进入同一份三维世界。

展开讲
1. 新 RGB-D 与相机产生候选点云；类似 SLAM 建图的一侧负责对齐旧地图、融合和优化 GS。这里说的是功能，不假设某个开源项目已经完整提供跟踪与回环。
2. 通过检查的新区域写回世界，下一轮从更新的 GS 渲染，所以刚刚探索的内容成为之后的几何约束。
3. 同时，新 RGB-D 和相机经过选择进入空间上下文，下一轮生成仍能看到这部分历史。两条反馈是原架构的关键。
4. 在静态探索时固定 t；动态情况写入对应的动态层或时刻状态，不能把不同时间的运动都不加区别地融进静态 GS。

## 07｜假设四：空间与时间分开控制，共用世界状态

开场句
我对 4D 的设想是先把操作分为两种：同一时刻换视角，或者同一视角看时间变化。

展开讲
1. 空间路径固定 t、改变 C：查询该时刻的静态背景和动态状态，渲染、生成并按需补充空间几何，复用前面的闭环。
2. 时间路径固定 C、推进 t：统一模型结合历史生成或重构下一时刻的 RGB-D，把变化写入动态 4DGS 或形变表示，再渲染新时刻。
3. 因此世界不是只有一份静态 GS，而是静态背景加动态层。C 和 t 也可以同时变化。完整模型仍要处理遮挡、多视角与时序一致性。
4. 这是一种可实现的控制 / 调度假设，不需要先声称底层网络完全解耦。实施时可以先验收静态闭环，再接动态；但动态分支在我的总体架构中一直保留。

## 11｜① 渲染：告诉模型，世界里已经有什么

开场句
渲染图是一份几何约束：这个相机位置上，已有世界应该长什么样。

展开讲
1. 输入是当前地图与目标相机，在固定时刻查询；输出包含粗 RGB、深度，以及哪些像素有可靠几何支持的有效性信息。
2. 缺口、遮挡后新暴露的区域和低置信区域交给下一步生成；不要把所有 alpha 或深度有效像素都等价为高质量真值。
3. 右图来自本地 3 帧输入建立的 GaME 场景，在输入相机上重渲染。它仅说明 GS 可渲染，非 Atlas 的结果，也不是专门的新视角质量验证。

过渡句
粗图提供了空间骨架，但它可能有洞或者粗糙，第二步负责生成完整画面。

## 13｜③ 重建：把新图变成可融合的几何

开场句
重建这一步解决的不是画面好不好看，而是每个像素究竟位于世界的哪里。

展开讲
1. 输入应包括新帧与重叠的历史关键帧。工程目标是利用已有相机或几何锚，约束当前批次的尺度和位姿。
2. MapAnything 输出深度、pointmap、相机内外参等；pointmap 是每个像素对应的三维点，不等于已经具备长期状态的地图。
3. 右图是本地测试第 0 帧的预测 z-depth，经 2–98 百分位归一化着色，仅为了说明几何中间量。当前包装器还是 RGB 入口，已知相机条件尚未接入其 CLI。

## 14｜④ 融合：让新几何进入旧地图

开场句
融合的关键不是再导出一个 PLY，而是让这轮结果成为同一个世界的新版本。

展开讲
1. 先用重叠区、相机约束或几何匹配，把新批次对齐到旧世界的尺度与坐标。
2. 再检查投影一致性、可见性和置信度，避免生成错误覆盖已知可信区域；必要时只接受部分新区域。
3. 最后为新增区域补 GS，并联合优化、剪枝；保存更新后的地图与必要优化状态，下一轮继续使用。GaME 可承担后半段，但坐标对齐、门控和跨进程恢复仍需工程适配。

## 17｜先用一张表，分清三个项目各自的工作

开场句
这三行对应三个不同问题：怎么生成新内容，怎么恢复几何，怎么维护可渲染的场景。

展开讲
1. WorldWarp 的直接演示入口是一张起始图加相机运动，可输出一段新视角视频，并留下用于生成条件的局部高斯缓存；后续段可以读取上一段视频。
2. MapAnything 可接一张或多张图。多视角输入最好属于同一场景、有重叠且时刻一致，输出深度、相机内外参、pointmap 等；本地点云 PLY 由包装器聚合导出。
3. GaME 接带相机参数的 RGB-D；完整场景变化处理还需要掩码。它优化的是当前场景的 Gaussians，既能保存资产也能保存场景状态。
4. 这三个项目不是三种同类型的视频模型，也不是三种可以无条件互换的 3D 模型。

过渡句

## 18｜WorldWarp：生成侧基线，自带局部几何与 GS

开场句
WorldWarp 是最接近我们生成侧闭环的现成基线，而且它已经有三维几何条件。

1. 本地 GUI 支持起始图、相机预设或自定义轨迹，并可用参考视频提取轨迹；文本可影响风格与提示。GUI 的文本生成首图属于额外入口，不表示直接生成完整三维世界。

## 19｜MapAnything：几何前端，把图像变成有坐标的点

开场句
MapAnything 的任务是恢复几何：图中每个有效像素在哪里，相机又在哪里。

展开讲
1. 原模型支持单图或多图，以及可选的相机标定、位姿、深度等几何输入，覆盖单目深度、SfM、MVS、相机定位、深度补全等任务。这里的任务覆盖不等于完整替换传统系统的所有工具和优化流程。
2. 当前 run_mapanything.sh 包装器只接 RGB 文件或目录，支持标记 observed、generated、rendered。source-kind 只是来源记录，不会自动提升模型可靠性。
3. 输出 pointmaps.npz、posed_rgbd.npz、pointcloud_fused.ply 和报告。点图是逐像素世界坐标；点云 PLY 是该次联合推理共享坐标中的体素聚合，不是跨批次 SLAM。
4. 可在功能上替换 WorldWarp 的 TTT3R/CUT3R 几何预测支路，或作为几何基线对比 VGGT / DUSt3R 类前端；张量组织、相机尺度与多帧状态不相同，不能直接换一个类名。
5. MapAnything 不负责生成未见新内容，不直接优化 GS，也不保存长期全局地图。上游虽有 COLMAP 格式导出与 gsplat 训练衔接，但 GS 是下游训练的结果，不是 pointmap 本身。
6. 默认权重和 Apache 权重都已经安装并做过推理。当前深度和尺度来自模型预测，没有真实标定精度验证；把生成帧或粗渲染当输入时要保留置信度与质量门控。

过渡句
有了带相机参数的 RGB-D，再由 GaME 把几何变成可维护的 GS 场景。

## 20｜GaME：地图后端，把 RGB-D 融合成可更新的 GS

开场句
GaME 是地图后端，不是另一个 RGB 到三维的预训练预测器。

展开讲
1. 输入不仅需要 RGB-D 和位姿，还要有匹配的 K；原生变化适应算法使用分割掩码。当前包装器用一个全图静态 mask 来验证静态融合，没有做 SAM 或运动分割。
2. 它按关键帧增补高斯，进行单帧与多帧优化，并用场景变化机制处理新增和过时几何；场景模型本身可导出为 PLY，还可保存包含优化相关状态的场景 checkpoint。
3. 可承担我们框架中的融合与地图优化模块，并替代 WorldWarp 中局部 GS 优化器的一部分功能。若要进一步变成跨段长期世界，还要接全局坐标锚、地图恢复和生成候选审核。
4. GaME 的 scene evolution 主要处理重新观察时场景已发生变化，例如椅子被移走。它不等于连续时间的 4DGS，不提供任意时刻查询或未来运动生成。
5. 源码直接使用输入 pose，并未自动运行相机跟踪和回环；这个类里字段名叫 estimated_poses 也不能证明它会估计相机。输入独立点云还需转换为所需 RGB-D / 相机数据，当前入口不是任意 PLY 直接合并。
6. 原生 GaME 构造器支持 checkpoint_path 与历史数据恢复，本地已测试重载；但包装器没有把重载模型继续接上新一轮 train 的 CLI。不要把原生恢复能力、重载验证和跨轮续图这三个层次混在一起。

## 26｜A1｜AR、扩散与场景时间，分别是什么？

开场句
这里澄清三种不同的轴，避免把 AR 和扩散误认为互斥。

展开讲
1. AR 指序列组织：在前面上下文条件下预测下一个元素。官网的元素可以包含不同模态，不能简单限制为按物理时间输出下一视频帧。
2. Rectified flow / 扩散指当前输出元素内部的生成过程，在潜空间中由噪声逐步恢复样本。
3. 物理时间 t 是场景状态查询条件，与序列索引 k、内部去噪步 s 是不同概念。固定 t 换相机仍可逐元素 AR 生成。

过渡句
落到开源组装时，接下来需要统一的不是网络形式，而是中间数据约定。

## 27｜A2｜统一中间格式：图像、相机、几何

## 30｜A5｜4D 的关键，是覆盖“相机 × 时间”

开场句
这个网格表示观测组织方式：一列是同一时刻的多相机，一行是同一相机的时间序列。

展开讲
1. 不同视角、同一时刻用于约束该时刻的空间几何；同一视角、多个时刻用于约束运动和变化。每一个格子可以来自真实采集，也可能来自生成候选，但两类证据的可靠性不能混为一谈。
2. 单相机的一行视频缺少其他视角，并不能唯一确定遮挡后或背面的动态几何。要生成可自由换视角的 4D 资产，就要补多视角证据或引入额外深度、运动与结构先验。
3. NoPo4D 这类候选负责从时空观测重建动态表达；它不是独立决定未来物体怎么运动的生成器。

帧数、输入类型和状态恢复分别是三个问题，不能只用一个“支持多少帧”概括。

展开讲
1. WorldWarp 用户可只提供一张起始图；内部 chunk 有帧数和 VAE 时间压缩约束，具体配置需一起校准。本地只做了 81 帧单段验证，继续多段仍需要显存、历史管理和质量验收。
2. MapAnything 当前输入至少一张，默认最多取 8 张；GaME 包装器默认只取前 3 张。两个 max-views 都要改成相同目标帧数，并注意 GaME 还会筛关键帧。多帧并不要求按固定 3 帧或 8 帧分组。
3. MapAnything memory-efficient 选项降低开销，不等于无上限在线流。静态重建优先同一时刻、多视角有重叠；动态帧盲目当静态多视图会出现冲突。
4. 原生 GaME 在已有超过 2 个关键帧后才进入 detect_additions 分支，因此前三个关键帧测试没有覆盖完整变化检测；但前三帧仍会创建 / 增补 GS 和优化，不是说前 3 帧完全不融合。
5. 跨轮运行要恢复优化器和关键帧相关状态、绑定世界坐标，并筛选可信生成区域。本地 wrapper 现阶段每次新建图，没有无限续图 CLI。
