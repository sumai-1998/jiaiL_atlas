日期：2026-09-22。结论依据为代码静态核查与官方论文摘要，尚未运行真实模型。

## 2. 它改变了哪一层

传统视觉生成通常学习以外观为主的 latent，生成 RGB 后再从 RGB 估计几何。GAE 的思路是先把几何基础模型的特征压缩成可生成的 latent，然后从同一个生成状态读出 RGB 与几何。

```text
观测图片 / 多视图
      ↓ 冻结的 DA3 编码器
四层几何感知特征
      ↓ 分层归一化、拼接、GAE 编码
几何原生 latent z
      ├── RGB 解码头 ──→ 图像
      └── 特征解码器 ──→ 四层特征 ──→ 冻结 DPT ──→ 深度与射线

噪声 + 参考 latent + 相机 + 文本
      ↓ 在上述 latent 空间训练的 flow 模型
生成 latent z_hat
      ├──→ RGB
      └──→ 几何读出 → 相机恢复 / 点云构建
```

论文将其定位为感知与生成共享的表征，不能简化成“给普通视频生成器额外加一个深度输出头”。[论文摘要](https://arxiv.org/abs/2609.24981)

## 3. 第一阶段：训练几何 codec

### 3.1 编码的是什么

[gae/pipeline.py](../../../GAE-GeometricAutoEncoder/gae/pipeline.py)中 `encode()` 接收 `[B,V,3,H,W]` 图像，进行相应归一化，经冻结 DA3 提取四层特征，再由 [GAECodec](../../../GAE-GeometricAutoEncoder/src/stage1/gae_codec.py)归一化、拼接与压缩。

公开配置支持 64 / 128 通道。D64 默认生成尺寸宽 672、高 378，DA3 patch 为 14，对应每视图 `64×27×48` 的 latent 网格。它是按视图组织的状态，不是空间中无视角依赖的全局体素网格，也不等同于 Wan 的时空压缩 latent。

codec 编码器输出均值和对数方差；codec 训练可重参数采样，flow 训练与推理使用后验均值，并按通道统计量标准化。不同阶段的归一化不能混用。

### 3.2 两条解码支路

- RGB 支路：学习到的 RGB head 从 latent 产生外观，发布 D64 配置含时空注意力。
- 几何支路：恢复四层 DA3 特征，经对应反归一化与冻结 DPT 得到深度、射线等结果。

冻结 DPT 的意义是让压缩后的特征继续被原有几何读出器理解。它约束特征语义，但**不保证所有生成状态都在正确几何分布内**；压缩、生成与 DA3 本身都可能出错。

### 3.3 为什么不只优化重建损失

源码和[方法映射](../../../GAE-GeometricAutoEncoder/docs/METHOD.md)列出了特征重建、KL、RGB、几何及表征组织损失。额外两项值得关注：

| 项目 | 约束位置 | 想解决的问题 |
|---|---|---|
| `L_tok` | 经投影的后验 token 与 C-RADIO 特征对齐 | 改善语义组织和生成空间性质 |
| `L_struct` | 原始后验均值中的 patch 相似关系对齐 DINOv2 | 保持空间及跨视图结构，防止只做 token 对齐损失结构 |

这些损失塑造的是 codec 瓶颈，而非仅约束扩散模型中间层。实现见 [repa_target.py](../../../GAE-GeometricAutoEncoder/src/stage1/repa_target.py)和 [train_codec.py](../../../GAE-GeometricAutoEncoder/scripts/train/train_codec.py)。对我们的启发是：能够重建的压缩空间，不一定天然适合稳定生成，需要同时评价可解码性与生成难度。

## 4. 第二阶段：在几何 latent 上生成

codec 冻结后，[GAEFlow](../../../GAE-GeometricAutoEncoder/src/stage2/models/dit.py)及其 temporal 版本学习噪声到几何 latent 的条件 flow。当前配方采用 x-prediction：网络预测干净状态，再转换成流速度用于数值积分。

条件包括文本、带尺度信息的 Plücker 相机射线，以及独立编码的干净参考 latent。相机进入注意力的方式见 [camera.py](../../../GAE-GeometricAutoEncoder/src/stage2/models/camera.py)；训练/推理的原点、平移归一化、射线尺度和 FOV 必须一起核对，不能因参数名含 metric 就保证绝对世界尺度。

### 一个与你们非常相关的细节：参考图必须独立编码

DA3 是多视图集合编码器。同一张首图与未来目标图一起输入时，其特征可能利用目标图的信息。如果训练时用这种首图特征作为条件，实际推理仅有首图就无法复现它。

[train_flow.py](../../../GAE-GeometricAutoEncoder/scripts/train/train_flow.py)明确区分全视图目标编码和 `images[:, :cond_num]` 的参考独立编码。干净参考作为条件 token 加入，参考条件副本的输出在预测头前丢弃；生成状态由 flow 更新。

这不是证明我们现有基线存在此问题，而是一条应普遍应用的审计原则：**条件必须仅由推理时可获得的信息构成。** “参考图是真实首图”并不充分，还要检查它的特征是否受到未来图像影响。

## 5. 实际生成与长序列如何运行

[scripts/demo/generate.py](../../../GAE-GeometricAutoEncoder/scripts/demo/generate.py)是公开单图入口，默认参数为：

| 参数 | 当前默认 |
|---|---|
| 分辨率 | 672×378（宽×高） |
| 单次视图数 / 总视图数 | 81 / 81 |
| 采样 | 50 步，CFG 2 |
| seed / 输出 fps | 42 / 12 |
| 长 rollout 重叠参考 | `roll-cond-num=1` |
| 相机 | 可读含 c2w、K 的 NPZ；也可生成 wander/orbit/spiral/drive 轨迹 |

默认单图入口只传一张真实参考；少量多视图参考能力需按底层 API / 评价入口的数据契约接入，不能把多个文件名直接传给 `--image`。

总视图超过每段视图数时，[eval_generation.py](../../../GAE-GeometricAutoEncoder/scripts/eval/eval_generation.py)使用上一段末尾的 latent 作为新参考，分段相机重新归一化，并去重重叠输出。它不是每段自动检索全部旧视图的 WorldCrafter 式长期记忆，也没有跨段持久 GS 更新。

脚本发现图片旁的相机文件时可能自动采用；明确配对评测应显式指定 `--poses`，生成自由轨迹应明确 `--free-rollout`。上游 wrapper 内部传入 `--dataset scannetpp` 作为入口参数，不应据此将用户的任意图片标注为 ScanNet++ 数据。

## 6. PLY 到底保存了什么

`save_pointcloud_ply()` 写出的字段只有 `x,y,z,red,green,blue`，是彩色点云。没有标准 GS 所需的尺度、旋转、不透明度和外观系数，因此 **PLY 扩展名相同，不代表与 WorldWarp 高斯 PLY 相同**。

当前点云构建直接使用 DPT 解码的射线原点、方向及配套深度：`point = origin + depth × direction`。相机恢复仍用于校验/相关流程，但不能把这套深度随意当作另一组 K/c2w 下的相机 Z 深度反投影。

跨段导出包含利用重叠区域作 Sim(3) 对齐的点云，以及未对齐版本。对齐是在输出几何层面处理坐标差异，不能声称模型内部从始至终已有一致全局地图。衡量运动控制时还应保留对齐前差异，避免对齐掩盖尺度漂移。

如需完整高斯资产，候选后处理为：生成 RGB＋解码几何 → 筛选一致点及视图 → 全局 GS 初始化与多视图拟合 → 留出视角验证。单纯把点云字段补齐为高斯参数，并不能得到高质量场景。

## 7. 与 WorldWarp、WorldCrafter 的关系

| 问题 | WorldWarp | WorldCrafter | GAE |
|---|---|---|---|
| 几何作用于哪里 | 粗渲染与有效性条件 | 历史编码和相机查询 | 被生成的 latent 状态及其解码 |
| 主链路 | 估深 → GS → 粗图 → 视频 | 历史 latent → 查询记忆 → 视频 | 几何 latent flow → RGB / 几何 |
| 是否需从生成 RGB 再估几何 | 本地跨段需要 | 主生成不需要显式估深 | 可直接从生成 latent 读出几何 |
| 长期记忆 | 最近窗口重新建模 | 全历史档案中检索 | 当前 rollout 主要末尾 latent 续接 |
| 原生完整 GS 资产 | 无统一持久 GS | 无 | 导出点云，非完整 GS |
| 最适合作为哪种对照 | 显式几何条件 | 可查询的隐式历史记忆 | 几何与外观共享的生成表征 |

它们不需要立刻串起来。先分别建立可靠对照，才能判断优势来自表示、记忆还是更强生成骨干。GAE 的 latent 维度、尺度与训练分布不同，不能直接替换 WorldWarp 的 VAE；把它送进 WorldCrafter RepEncoder 也需要重新适配训练。

## 8. 对我们任务的具体帮助

### 优先级一：验证共同状态是否减少 RGB—几何不一致

同一输入和相机下，比较 GAE 直接解码几何与从其生成 RGB 经独立模型估计的几何。量化两者的相机、重投影和深度关系，同时对有真值数据评价准确性。

GAE 和其 DA3 解码头具有共同偏差，不能仅用同一 DA3 再评分就证明真实三维正确；需要独立估计器或标定/合成真值，并报告估计失败。

### 优先级二：几何生成与 GS 资产之间的接口

尝试从直接解码点云初始化 GS，与“生成 RGB → MapAnything → GS”比较。固定输入视频及 GS 优化预算，先隔离几何来源差异，再比较不同生成方法。尤其检查深度定义、世界坐标与分段尺度，不复用当前 WorldWarp 反投影公式而不校验。

### 优先级三：表征与长期记忆的组合研究

GAE 提供可解码的状态，WorldCrafter 提供目标相关的历史读取。可研究在几何原生 latent 上维护带来源的记忆，但这属于新训练方案，不是安装两个仓库即可得到的能力。

仍有价值的问题是：生成几何不一致时如何拒绝写入；后续真实视图如何纠正旧 latent；旧世界的正确部分如何在修正时保持。共同 latent 已是该工作的核心贡献，不能再作为我们未经比较的原创点。

### 对“物理理解”的边界

深度、相机和点云是空间几何，不含已验证的质量、受力和接触动力学。GAE 更贴近几何生成表征，并未因此完成物理世界模拟；我们的物理任务仍需动作监督和独立状态转移验证。

## 9. 开源完整性与部署建议

相较此次 WorldCrafter 快照，GAE 提供了更直接的 codec/flow 训练入口、数据准备、评价脚本与配置，详见 [CODEBASE.md](../../../GAE-GeometricAutoEncoder/docs/CODEBASE.md)。这有利于研究复现，但代码存在不等于数据已准备或训练已验证。

当前发布模型入口是 `TencentARC/GAE-D64-1B`。64/128 两种配置存在，不代表两个大小的所有权重都已在本地或已核验。模型统计量、codec、flow 与冻结 DA3 组件必须匹配，不能漏加载 latent 统计量后仍宣称同一模型。

[pyproject.toml](../../../GAE-GeometricAutoEncoder/pyproject.toml)要求 Python 3.10–3.12、PyTorch 2.5.1，且依赖 DA3、xformers 等；与 WorldCrafter 的 PyTorch 2.10 环境应分开。`run_demo.sh` 会自动建环境、安装和下载，不能作为纯查看命令执行。本次未运行该脚本。

训练开销需要在确定分辨率、视图数、更新模块和卡型后测量。81 个视图的几何 latent 注意力成本不可仅由“1B”模型名称估计，也不能将配置里的巨大 epoch 上限解释为作者实际完成的训练周期。

[LICENSE.txt](../../../GAE-GeometricAutoEncoder/LICENSE.txt)限定学术用途，禁止非学术、商业或生产用途，需保留许可信息。当前项目可作为学术研究对照，未来产品复用另行核对授权。

## 10. 当前建议

短期先部署官方 D64 单图示例，分别检查 RGB、直接解码深度、点云和相机；通过后再在我们的雕像与 classroom 上评测。每一步保留条件与输出来源，不能把源码分析或 stub 测试当成真实生成结果。

从研究选题看，可以把三个底座组织为：**WorldWarp 检验显式几何条件，WorldCrafter 检验历史读取，GAE 检验生成状态表征。** 在这些对照上研究来源感知的长期纠错，比把全部模型强行串联更有助于定位贡献。
